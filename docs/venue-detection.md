# 场馆自动识别与切换

1.4.0 起默认 `venueMode: "auto"`。保存的 `venueId` 只用于打开初始页面，不作为本次可预约场馆的依据。程序取得学校官方羽毛球目录后，按用户时段优先级、场馆优先级、场号优先级组成候选。只尝试用户选择的日期与时段。

## 核对哪些字段

| 数据来源 | 使用字段与约束 |
| --- | --- |
| 官方场馆目录 `campus/venue/info?sportType=156` | `id` / `venueSiteId`、`venueId`、`siteName` / `enSiteName`、`sportType` / `sportName`、`campusId`、`isSupportReservation`、`notShowSite`、停用/删除标志、`spaceCount`、`advanceDay`、`reservationHour`、开放时间、须知代码、收费和次数限制信息 |
| 场馆详情 `front/website/venue_sites/{id}` | 与目录核对场地 ID、上级分类、校区、运动类型、中英文名称、预约开关、须知代码；缺失或互相矛盾的身份资料会阻止选场 |
| 页面入口与提示 | URL 中的场地 ID、场馆标题、登录姓名、预约须知、08:00 查询限制、迁移/恢复提示、表格加载状态 |
| 每日排期 `reservation/day/info` | 请求 `venueSiteId` / `searchDate`；`siteParam.venueSiteId` / `siteName`；`reservationDateList`、`reservationDateSpaceInfo`、`advanceReservationDays`；每行所属场馆、真实场地 ID、中英文场号；`spaceTimeInfo` 中时段 ID / 起止时间；占用状态、费用、停用/迁移备注 |
| 选中摘要与提交参数 | 日期、场号、一小时时段、零元金额；实际 POST 的 `venueSiteId`、`reservationDate`、`reservationOrderJson` 中唯一的 `spaceId` / `timeId`，与刚核验的排期一一对应 |
| 订单及 Pay 页面 | 对照原有订单的场馆、日期、唯一时段、金额与状态；提交结果不明确时先回查，防止换场馆后重复下单；只有用户启用自动零元确认才点击 Pay |

`venueId` 在官方目录中是**上级分类 ID**，不等于预约页面的场地 ID。球场显示的“1号”也不等于排期的 `spaceId`：篮球场入口 346 的 1 号场曾使用 `spaceId=76`。程序分别核对这些标识，不互相替代。

目前识别范围为北航国新院校区 `187`、羽毛球运动 `156`。以后出现新的场地 ID，只要仍在该校区的当前官方羽毛球目录中、已启用预约，且详情/排期一致，即可进入候选；不会仅靠名称猜测任意场馆。新增运动或校区须明确修改适配。

## 放号与切换

- 预热时读取当前可访问页面。遇到“当日8点以后才能查看当天的预约”，正常关闭该提示后继续等待；不提前勾选被弹窗遮挡的预约表单。
- 等待放号时，两个已知历史入口都提前只读预热，处理各自须知倒计时；未在当前官方目录的入口仍不能选场。放号时切换到已经预热的入口可复用页面。
- 预约须知等待网站倒计时结束后再关闭。按实际遮挡关系处理最上层弹窗；须知中介绍 08:00 开放不等同于当前禁止查询。未知弹窗会记录原因并停止该入口。
- 到本次开始选场时，重新通过网站自身的请求组件获取目录。该组件会生成新的时间戳和签名，不重放五分钟前的认证请求。
- 重试期间最多每两秒重新检查目录。当前目录移除的旧入口，即使仍能打开并显示 ¥0，也不进入新预约候选。场馆接口数据冲突或迁移提示会触发再次核对。
- 目录同时列出多个合格场馆时，默认训练场 `1` 优先、篮球场 `346` 其次，再考虑其他官方入口。一个入口的目标日期未开放，可继续检查其他合格入口。
- `spaceCount` 仅是目录计数，不代表最大场号。保留用户场号顺序，按目标日期真实排期中的场号、所属入口、状态与场地/时间 ID 验证；没有该场号或不可预约时跳到下一候选，不擅自添加其他场号。
- 自动模式下初始旧入口失效时，可只读访问其他已知入口以取得当前官方目录；只有目录中合格且通过详情/排期核验的入口可选。固定入口模式不会擅自改馆。
- 日期开放范围以学校实际排期为准，不能仅凭 `advanceDay` 数字推断未来日期已开放。界面切换“现在开始 / 等到 08:00”时，自动日期分别按今天后两天或本次放号日后两天计算；手动选定的日期保持不变，运行开始后日期固定。

可在 `config.json` 使用 `venuePriority: [1, 346]` 修改入口优先级。需要限定单个入口时，可使用 `venueMode: "fixed"` 与已知 `venueId`；即使固定入口，也必须通过当前官方目录核验。默认推荐自动识别。
