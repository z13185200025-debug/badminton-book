# 滑块通过后，订单仍提示验证码非法校验

网站有两步验证：滑块位置检查，以及提交订单时的二次校验。滑块返回成功不能证明订单已被接受。HTTP 200 也可能携带业务错误 250。

现有失败日志的滑块检查返回成功，订单随后明确拒绝。失败发生在订单二次校验，并非已经确认图片拼错或网络断开。

## 2026-11-13 的一次对照

对照使用相同的预约日期、时段和场号优先级，只在验证码图片加载完成后增加 1000 ms 等待，保留网页原有的校验后提交间隔。只尝试一次，关闭自动 Pay。

| 观测 | 08:00 运行 | 10:36 对照 |
| --- | --- | --- |
| 验证码返回至开始检查 | 440 ms | 1435 ms |
| 滑块检查结果 | 0000，通过 | 0000，通过 |
| 检查结束至发出订单 | 506 ms | 509 ms |
| 二次校验内容比较 | 与当前滑块一致 | 与当前滑块一致 |
| 订单业务码 | 250，拒绝 | 200，接受 |
| 验证 / 提交次数 | 1 / 1 | 1 / 1 |
| Pay | 未到达 | 页面就绪，未点击 |

对照从开始选场至 Pay 显示约 3.10 秒，至 Pay 就绪约 3.40 秒；这是高峰之外的一次实际观测，不是 08:00 的性能保证。产生了待确认订单，未完成预约；之后未再次查询其状态。

延长等待与这一次成功同时出现，支持采用保守等待，但不能证明因果关系：时段、服务器负载和验证码都已变化。历史上也有挑战等待约 427 ms 的成功记录，因此不能把“低于 1 秒”当成已证实的拒绝阈值。

## 参考资料与判断边界

网站前端采用与 AJ-Captcha 相符的两阶段流程。其[官方集成说明](https://ajcaptcha.beliefteam.cn/captcha-doc/captchaDoc/java.html)指出，多节点部署若使用各自的本地缓存，可能因缓存不同步而验证失败。[参考源码](https://github.com/anji-plus/captcha/blob/master/core/captcha/src/main/java/com/anji/captcha/service/impl/BlockPuzzleCaptchaServiceImpl.java)在滑块通过后写入一次性的二次校验记录，订单校验时检查并消费该记录；此实现没有最短完成时长判断。

学校的部署版本、自定义风控、缓存配置及业务码 250 的内部原因不可见，上述机制是排查线索，不能当作学校后台故障的证明。当天两次请求均收到 HTTP 200，记录中没有网络请求失败或限流事件；普通断网或超时不是已观察到的直接失败原因。

## 当前处理

图片加载后默认主动等待 1000 ms，再操作滑块。可在 `config.json` 设置 `captchaReadyWaitMs`，允许 0–1000 的整数毫秒，省略时使用 1000。等待发生在本地，不会额外查询学校，也不会修改网页原有约 500 ms 的成功回调。技术详情分别记录主动等待、挑战等待、检查接口和校验后提交耗时。

每次只验证、提交一次；验证或订单拒绝后立即停止，不重新取挑战、不自动回查或重提。成功提交后的订单列表回查和最终确认回查各执行一次，未能确认时提示手动核对。旧版 `maxCaptchaAttempts` 配置不会增加实际尝试次数。

## 1.4.2 的历史处理（自动重试已在 1.4.4 停用）

- 按每个请求绑定挑战与检查响应，防止乱序响应污染诊断。挑战响应延迟解析、刷新新挑战时仍保留原校验的证据。
- 在本地内存中读取网页已经产生的校验内容，比较它是否对应同一次滑块检查。不生成、不替换、不重放验证码证明。确认内容不一致时停止提交；无法识别格式时明确显示无法核验，不标为一致。
- 首次尝试维持原速度。仅在收到明确验证码拒绝、并回查确认没有有效订单后，重新取得验证码恢复一次。恢复时拖动前额外等待 600 ms，检查完成后至少等满 1000 ms 才发出订单。网站原有约 500 ms 等待计入这 1000 ms，避免叠加成 1500 ms。
- 每次下单失败先回查订单。超时、断网或不明确的返回不触发盲目重试。一次恢复仍被拒绝则停止。
- 日志区分请求准备、实际发出、本地等待和接口响应。界面分别展示滑块结果、二次内容比较、校验后提交间隔和订单结果。

恢复等待针对可能的处理时序问题，是有界的缓解措施，不代表已确认或修复学校后台根因。需要后续正常预约的服务端结果验证有效性。

## 隐私与证据边界

挑战令牌、密钥、加密校验串和坐标只作内存比较，不写入新增诊断。运行日志仍可能包含本人订单信息；分享前请脱敏。新增日志能判断客户端内容是否一致，不能读取学校缓存或证明服务器采用何种验证配置。
